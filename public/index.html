We build, ship and run a hotel system, end to end.

devmatiker is a student team on the datamatiker programme at UCL in Odense. Our project is NF Hotel: the back office for the staff, online booking for the guests, a mobile app, and the servers, pipelines and monitoring that keep it all running.

The project: NF Hotel

  • Back office

    Staff manage bookings, rooms and guests in a web application. Each role (Manager, Receptionist, Housekeeping) sees and does only what it is allowed to.

  • Guest booking

    Guests find a free room and book it online, and later open their own booking with the booking number and their e-mail address.

  • Mobile app

    Housekeeping and reception work with the rooms from a Flutter app that talks to the same API as the back office.

  • Operations

    We run it ourselves: our own server, automatic deploys when every check is green, monitoring with alerts, backups and a written plan for when things break.

How we build it

Application
C# and .NET with Clean Architecture: a Blazor web application and a separate database API, so only one process ever touches the database.
Data
PostgreSQL, with migrations applied by the pipeline and nightly encrypted backups copied off the server.
Mobile
Flutter, signing in with a short-lived staff token and no shared secret in the app.
Platform
Docker containers on a Proxmox virtual machine, reached privately over Tailscale and publicly through Cloudflare Tunnel, with no port opened at home.
Pipeline
GitHub Actions: build, tests, end-to-end tests in a browser, a security scan of the running site, image scanning and signed releases, then a deploy with automatic rollback.
Monitoring
Prometheus, Loki and Grafana, with service level objectives and alerts in Discord.
Process
Every piece of work is planned as a milestone with measurable criteria, reviewed, and decided in architecture decision records.
